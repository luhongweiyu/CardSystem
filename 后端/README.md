# 卡密系统后端

这是一个 Go + Gin + GORM + MySQL 的单体卡密服务。系统同时提供两种彼此独立的卡密模式：
点卡按余额扣点，时长卡在卡密自身保存固定时长和到期时间。两种模式使用不同的数据表、接口和管理页面，
不会把两套计费字段混在同一张卡里。

## 运行

1. 在 `config.yaml` 填写 MySQL 连接信息和网站端口。
2. 运行 `go run .`；启动时会自动创建或补充公共表、点卡表和时长卡表。
3. 管理端前端构建产物可放到 `assets`，后端也可以只作为 API 服务运行。

点卡和时长卡都按新表结构运行，不自动迁移旧 `user_son` 或旧卡表数据；正式部署前请备份旧库，并使用新库初始化。旧代理价格 JSON 只按原点卡格式保留，时长卡价格锚点需要按代理、软件和分钟数人工迁入 `duration_card_agent_price`。

系统支持 HTTP，不强制 HTTPS。开启卡密安全模式后，请求需带 `timestamp`、`nonce` 和 `sign`；POST JSON 按原始 JSON 签名，GET 或无 JSON 的 POST 按查询字符串签名。响应会返回 `sign` 和 `nonce`，签名不能替代传输加密。

本服务端的客户端接口前缀是 `/point_card/*` 和 `/duration_card/*`，旧 `/card/*`、`/duration/*` 不再注册。需要继续使用旧客户端时，应让旧客户端连接旧服务端；新旧服务不要同时写入同一个数据库。

## 数据表职责

| 表 | 职责 |
| --- | --- |
| `user` | 管理员账号、密码原值和密码哈希（认证只使用哈希） |
| `user_info` | 管理员接口签名、公告、联系方式等设置 |
| `agent_account` | 代理账号、密码原值、密码哈希、代理余额和代理价格 |
| `software` | 管理员的软件、点卡默认授权时长、心跳间隔、自动离线时间、时长卡暂停扣除分钟数和公告 |
| `point_card_<管理员名>` | 该管理员的点卡基础资料和唯一当前余额 `point_balance` |
| `duration_card_<管理员名>` | 该管理员的独立时长卡、固定时长、激活时间、到期时间和在线 needle |
| `duration_card_agent_price` | 每个代理账号按软件配置的时长卡价格锚点 |
| `duration_recharge_card` | 独立时长充值卡、单次充值分钟数、面额次数和剩余次数 |
| `point_period_price` | 软件允许的点卡计费方案、授权时长及每次扣点数 |
| `point_device_session` | 卡密在每台设备上的当前授权会话、`device_id`、别名、`needle` 和心跳时间 |
| `point_ledger` | 每次真实余额变化的一行审计流水，后台仅保留最近 30 天 |

卡密表不再使用 `end_time`、时长卡状态或 `window_expires_at`。设备授权时间只在 `point_device_session.authorized_until` 中保存；流水不保存设备列，设备 ID 和别名快照写在 `remark`。

上面的说明只针对点卡表；`duration_card_<管理员名>` 是独立的时长卡表，允许使用 `end_time`、未激活和到期状态，
这些字段不会被点卡接口读取。

当前继续使用“每个管理员分别拥有点卡表和时长卡表”的租户隔离方式，代码统一校验动态表名。管理员规模明显增长后，可以把这层替换为统一卡表加 `admin_id`，或迁移到分库；当前不提前引入物理分区。

启动时的 `AutoMigrate` 只负责创建或补充表结构，不负责导入旧卡密等业务数据。管理员和代理账号会同时保存 `password` 原值与 `password_hash`；登录验证只比较哈希，接口不会返回原值。`password_hash` 允许为空；为空的账号不能登录，但不会影响其他账号或服务启动。

## 点卡计费规则

- 新设备（管理员、卡密、`device_id` 组合不存在）登录扣除所选点卡计费方案的点数；软件编号始终从卡密记录读取。
- 同一设备在 `authorized_until` 之前重复登录不扣点；若明确提交了新的有效 `period_minutes`，只更新下一次续费时长。
- 到期后用最后心跳判断是否可能仍在线：`last_heartbeat_at + online_grace_minutes × 1分钟`。推断窗口跨过旧到期时间且当前时间尚未超过窗口时，从旧到期时间续一个授权时长；否则视为停止后重新运行，从当前时间续一个授权时长。自动离线时间为 0 时按 60 分钟处理。
- 授权时长按管理员配置的计费方案执行；自动离线时间由软件单独配置，不影响心跳间隔和计费周期。
- 点卡和时长卡授权期内的普通心跳先更新各自的进程内缓存；每条脏缓存达到配置间隔后，由下一次心跳写入数据库，不使用定时扫描。登录、续费、退出、冻结、暂停、恢复、充值、删除和软件变更会先同步并失效相关缓存。
- 后台每分钟清理到期会话。推断为离线的会话删除；推断仍在线的会话自动扣除对应方案点数并延长授权。方案不可用或余额不足时直接删除会话，配置修复或补点后由客户端重新登录。
- 退出可省略 `device_id`，省略或传空值时按空字符串查找会话；也可提交 `needle` 作为附加校验。接口直接删除会话行，不写“退出状态”。
- `device_id` 可选，省略时按空字符串处理，登录与心跳必须保持一致；多个客户端都省略时会共用一条空设备会话。`device_alias` 仅在登录时可选、可重复；`needle` 是服务端随机生成的心跳校验令牌，不承担设备唯一性。
- 每张卡最多保留 1000 台设备会话；达到上限后只拒绝新设备登录，已有设备重复登录不受影响。
- 余额更新、流水写入和授权时间更新在同一数据库事务中完成，并按卡密行再会话行加锁，避免并发登录重复扣点。

删除卡密会删除当前会话，但不会立即删除流水；流水由后台定时清理，仅保留最近 30 天。同名卡密删除后可以再次生成；新一代会写入“生成卡密初始点数”流水，因此保留期内的新旧流水仍能按时间和备注区分。

代理价格使用扁平 JSON 保存，格式为 `{"软件ID": 每1点卡点数消耗的代理余额}`，例如 `{"1": 0.25}`。映射中没有某个软件即表示未授权；价格必须大于 0 且最多两位小数。代理生成一批点卡后的总费用按整数点向上取整。

## 时长卡模式

- 管理端使用 `/admin/duration_card/*` 和前端“时长卡”页面，点卡页面不会显示时长卡。
- 生成时指定软件、卡面时长（5 分钟至 36500 天）、卡密文本、备注和可选最晚激活时间；`0` 表示生成后立即激活，`-1` 表示不限制。
- 首次调用 `POST/GET /duration_card/card_login` 激活未激活卡；软件编号从时长卡记录读取，不需要客户端提交。重复登录只刷新服务端 `needle`，不会重复延长时间。
- `POST/GET /duration_card/card_ping` 只接受当前 needle；同一张时长卡同时只保留最后一次登录的 needle。`/duration_card/card_logout` 清除在线校验但不扣除或增加时长。
- 时长卡心跳命中进程内缓存时只更新内存中的最后心跳；达到 `心跳缓存.同步间隔分钟` 后由下一次心跳写入数据库。卡密状态、激活、暂停、恢复、充值和续费仍以数据库为准，相关操作会同步并失效缓存。
- `/duration_card/query` 和访客 `/visitor/查询时长卡` 查询固定时长、激活状态、到期时间；时长卡不产生点数流水。
- 代理账号的时长卡发卡权限和价格单独配置在 `duration_card_agent_price`，不复用点卡每点价格。一个软件可配置多个时长价格锚点；代理生成未命中锚点的时长时，在相邻锚点之间取较高平均单价折算，精确命中则使用锚点原价。超出启用锚点范围的时长拒绝生成。
- 管理端使用 `/admin/duration_card/agent_price/list|save|delete` 管理锚点；代理使用 `/agent/duration_card/price/list` 查询可用价格、`/agent/duration_card/price_preview` 预览扣款、`/agent/duration_card/create` 发卡。预览仅供展示，正式发卡时后端会在扣款事务内重新计算。
- 代理可通过 `/agent/duration_card/list|detail|save|state|delete|renew` 管理自己生成的时长卡；续费按当前时长价格锚点重新计价，并与代理余额扣减放在同一事务，暂停卡续费会累加暂停剩余分钟。
- 时长充值卡独立保存在 `duration_recharge_card`，管理员和代理分别使用各自前缀下的 `/duration_recharge_card/*` 管理；代理发卡按“单次充值时长 × 可用次数 × 卡数”计价。
- 访客可查询和使用时长充值卡，也可按软件配置的 `pause_deduct_minutes` 暂停或恢复时长卡。暂停时一次性扣除配置分钟数，恢复时从当前时间继续剩余分钟。
- 已激活或已暂停的时长卡还可调用 `/duration_card/recharge`，使用另一张同软件、未激活且状态正常的时长卡进行一次性充值；充值来源会永久标记为已用于充值，暂停卡只累加暂停剩余分钟。

### 旧时长数据迁移说明

系统不会自动迁移旧数据。迁移前先备份数据库，并在停服状态下完成以下人工处理：

1. 从旧 `card_<管理员名>` 中筛选确认属于时长卡的记录，写入 `duration_card_<管理员名>`；`available_time` 天换算为 `duration_minutes`，旧 `ID子账号` 写入 `agent_id`。
2. 旧 `storage_time` 天换算为 `paused_remaining_minutes`；有暂停余额的记录将 `card_state` 设为暂停状态 `5`，并清空 `end_time`、`needle` 和最后心跳。
3. 旧 `visitor_recharge` 写入 `duration_recharge_card`；`add_time` 天换算为 `duration_minutes`，`face_value/balance/expiration_date/ID子账号` 分别对应初始次数、剩余次数、有效期和 `agent_id`。
4. 核对数量、状态和时间后，再从旧点卡表删除已经迁出的时长记录；不要让同一条旧记录同时被点卡和时长卡业务读取。

## 配置项

- `网站.端口`：监听端口，默认 `802`。
- `网站.可信代理`：允许提供真实客户端 IP 的反向代理地址。
- `api.每小时请求上限`：单个管理员卡密 API 的进程内整点限额。
- `api.最大请求字节`：请求体上限，默认 2MB。
- `心跳缓存.同步间隔分钟`：单条脏心跳写入数据库的间隔，允许 15 至 60 分钟，默认 15 分钟；达到间隔后由下一次心跳触发同步，不再定时扫描缓存。
- 心跳缓存保存在当前 Go 进程内，点卡按管理员、卡密、设备 ID 定位，时长卡按管理员、卡密定位；现阶段按单后端实例运行，将来部署多个后端实例时应改用 Redis 等共享缓存。服务重启会丢失尚未同步的最后心跳，但不会丢失授权时长或余额。
- `software.online_grace_minutes`：软件自动离线时间，单位分钟；新增软件默认 60 分钟，设置为 0 时按 60 分钟处理，非零值必须为 5 至 4320 分钟。
- `software.pause_deduct_minutes`：时长卡每次暂停扣除的分钟数；`0` 表示关闭暂停功能。
- 默认授权时长、点卡计费方案和客户端登录参数统一按分钟使用（5 至 4320 分钟）；数据库内部继续按秒保存，接口读写时负责换算。
- `管理员注册.启用`：是否开放管理员注册，默认关闭。注册请求距离上次读取满 10 分钟时才重新读取配置；无请求时不读取，无需重启服务。

详细请求字段和响应示例见 [点卡API.md](./点卡API.md)。

管理端设置接口只返回 `api_password_set` 状态，不返回接口安全密码正文；替换
或清除密码请在设置页执行对应操作。
