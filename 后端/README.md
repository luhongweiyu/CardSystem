# 卡密系统后端

这是一个 Go、Gin、GORM、MySQL 服务，同时提供彼此独立的点卡和时长卡模式。两种模式使用不同的数据表、接口和管理页面，不把两套计费字段混在一起。

## 运行

1. 在 `config.yaml` 填写数据库连接信息和网站端口。
2. 运行 `go run .`，服务会自动创建或补充当前版本所需表结构。
3. 管理端构建产物可放到 `assets`；后端也可以只作为 API 服务运行。

服务支持 HTTP，不强制 HTTPS。接口安全签名不能替代传输加密；生产环境应限制管理端和数据库的网络暴露范围。

新客户端接口前缀是 `/point_card/*` 和 `/duration_card/*`。为兼容旧时长卡客户端，仍保留 `/card/card_login`、`/card/card_ping` 两个旧接口；其他旧 `/card/*`、`/duration/*` 路径不注册。旧接口使用旧签名协议，两个服务不要同时写同一个数据库。

## 数据表职责

| 表 | 职责 |
| --- | --- |
| `user`、`user_info` | 管理员账号和管理员设置 |
| `agent_account` | 代理账号、余额和代理配置 |
| `software` | 软件、心跳、自动离线时间、公告和时长卡暂停设置 |
| `point_card_<管理员名>` | 管理员独立点卡表和当前点数余额 |
| `duration_card_<管理员名>` | 管理员独立时长卡表、固定时长和到期信息 |
| `point_period_price` | 点卡可用计费周期和价格 |
| `duration_card_agent_price` | 时长卡代理价格锚点 |
| `duration_recharge_card` | 独立时长充值卡 |
| `point_device_session` | 点卡设备授权会话和心跳时间 |
| `point_ledger` | 点卡真实余额变化流水，后台只保留最近 30 天 |

`AutoMigrate` 只负责创建或补充表结构，不负责导入旧业务数据。旧 `card_<管理员名>` 仅作为时长卡迁移来源，不作为运行时卡表。

## 模式说明

### 点卡

点卡余额保存在管理员的 `point_card_<管理员名>` 表中，授权会话保存在 `point_device_session`。同一管理员、卡密、设备组合只有一条会话；普通心跳使用进程内缓存，达到同步间隔后由下一次心跳写入数据库。余额、流水和授权更新必须在同一事务中完成。

点卡计费周期按分钟配置，允许范围和接口字段以 [点卡API.md](./点卡API.md) 为准。软件的自动离线时间独立于心跳周期和计费周期。

### 时长卡

时长卡在 `duration_card_<管理员名>` 表中保存固定时长和到期时间。首次登录激活，重复登录不重复延长；暂停、恢复、续费和充值使用时长卡自己的业务逻辑，不读取点卡余额或点卡会话。

详细请求参数、响应和客户端行为见 [点卡API.md](./点卡API.md)。

## 旧时长卡迁移

只有 `config.yaml` 中设置：

```yaml
迁移: true
```

服务启动才会执行迁移检查。只处理目标 `duration_card_<管理员名>` 不存在、来源 `card_<管理员名>` 存在的管理员；成功后将旧表改名为 `card_<管理员名>_bak`，不会覆盖已有备份表。迁移完成后建议改回 `迁移: false`。

迁移前应备份数据库并停止旧服务。迁移会读取旧管理员、旧代理和旧时长卡，价格配置、`visitor_recharge`、点卡会话及点数流水不迁移；发现表、密码、卡密或代理映射冲突时会停止，不改来源表。

## 主要配置

- `网站.端口`：监听端口，默认 `802`。
- `网站.可信代理`：允许提供真实客户端 IP 的反向代理地址。
- `api.每小时请求上限`、`api.最大请求字节`：接口限流和请求体上限。
- `迁移`：旧时长卡迁移开关，默认 `false`。
- `心跳缓存.同步间隔分钟`：心跳脏缓存写入数据库的间隔，按当前实现范围配置。
- `管理员注册.启用`：是否开放管理员注册；配置会按注册请求间隔重新读取，无需重启。
- 软件的自动离线时间和时长卡暂停扣除分钟数在管理端的软件设置中配置。
